# 国际化（i18n）与汉化说明

VenvStudio 的界面文本有两层翻译机制。理解这两层的分工，是改词、加语言、
排查「某个地方没翻译」的前提。

---

## 一、两层机制

### 1. 键值层：`tr(key)`

`src/utils/i18n.py` 里的 `tr()`，按 key 取词：

```python
from src.utils.i18n import tr
QPushButton(tr("new_environment"))      # -> "新建环境"
```

- 词表：`src/utils/i18n_data/<lang>.py`，每个语言一个字典（`en`、`zh`、`tr` …）。
- 适合**新写的代码**：文案改了，key 不用改。
- 缺词时回退到英文，绝不返回空串。

### 2. 文本层：`render(text)` + 运行时重译

项目里绝大多数控件是用英文字面量直接构造的（`QLabel("Refresh")`、`QTabWidget.addTab(w, "Installed")`）。
把它们逐个改成 `tr()` 需要动几万行，风险远大于收益。所以改成**控件建好之后再翻译**：

```
src/utils/i18n_qt.py
  localize_widget(w)   # 逐项翻译 windowTitle/text/title/placeholder/toolTip/tab/表头/菜单项
  localize_tree(w)     # 递归整棵控件树（首次出现时只做一次）
  install(app)         # 装一个全局事件过滤器：控件 Show 的时候翻译它
  retranslate_all()    # 语言切换后，把所有窗口按「英文原文」重新渲染一遍
```

词表在 `src/utils/i18n_data/zh_ui*.py`，key 就是**控件上的原始英文文本**：

```python
UI_TEXT = {
    "Rename Environment": "重命名环境",
    "Filter by package name…": "按包名筛选…",
}
```

关键设计有两点：

- **`render()` 对没收录的文本原样返回**。所以词表不完整时界面退化成英文，
  不会出现空白、占位符错位或乱码。
- **每个控件会记住自己的英文原文**（`canonical()` 负责把中文反向映射回英文），
  切换语言时是「按原文重新渲染」，而不是把中文再翻译一次 —— 这就是「不重启就换语言」的实现方式。

### 刻意**不**自动翻译的东西

| 对象 | 原因 |
|---|---|
| 表格单元格、列表项 | 里面是数据（环境名、路径、包名），翻译会破坏后续比较 |
| 下拉框条目（QComboBox item） | 同上：很多逻辑靠 `currentText()` / `itemData` 判定 |
| 代码片段、命令、日志正文 | 属于内容而非界面 |

需要翻译的少数「组合式」控件（例如侧栏 `SidebarButton`，显示文本是
`"  📚  学习"` 这种「图标 + 空格 + 词」拼出来的），走另一条路：
控件暴露 `_i18n_rebuild` 回调，切换语言时自己用 key 重新拼。见
`src/gui/widgets.py` 的 `SidebarButton(label_key=...)`。

## 二、语言切换

| 入口 | 位置 |
|---|---|
| 设置页 | `设置 → 外观 → 🌍 语言` 下拉框，选中即生效 |
| 菜单栏 | `视图 → 🌍 语言` |
| 首次启动 | 无保存值时调用 `system_language()` 跟随系统语言 |

切换流程（`settings_appearance.py::_on_language_selected` 与 `window_menu.py::_switch_language`）：

1. `config.set("language", code)` —— 先落盘，避免重绘异常丢掉选择；
2. `set_language(code)` —— 通知所有监听者；
3. `i18n_qt.retranslate_all()` —— 遍历所有窗口按英文原文重新渲染；
4. `apply_layout_direction()` —— 阿拉伯语切换为 RTL 布局。

**不重启、不丢失当前状态**（当前页、选中的环境、正在编辑的设置都保留）。

## 三、改词 / 补词

### 查看还有哪些没翻译

```bash
python tools/i18n_extract.py            # 覆盖率概览（按文件）
python tools/i18n_extract.py --missing  # 列出未翻译的界面字符串
python tools/i18n_extract.py --json out.json
```

`tools/i18n_extract.py` 用 AST 扫描所有 `QLabel` / `setText` / `addTab` /
`QMessageBox.warning` 之类的调用，把「真正会显示给用户」的字面量挑出来，
再和词表比对。它跳过了字符串拼接产生的碎片 —— 那些碎片的最终文本和原文不等，
翻译了也不会生效。

### 加一条翻译

在对应的 `src/utils/i18n_data/zh_ui_*.py` 里加一行，**key 必须与源码里的英文逐字节一致**
（包括 emoji 和空格）：

```python
UI_TEXT = {
    "Open the environment folder in your file manager": "在文件管理器中打开环境目录",
}
```

文件分工：

| 文件 | 内容 |
|---|---|
| `zh_ui_core.py` | 主窗口、菜单、环境对话框、通用词（确定 / 取消 / 删除…） |
| `zh_ui_pages.py` | 设置页、包管理、项目页、启动器 |
| `zh_ui_catalog.py` | 预设说明、侧栏提示、较长的帮助文案 |
| `zh_ui_packages.py` | 包目录的一行描述（`constants.py` 里的 `desc`） |
| `zh_ui_dialogs.py` | 日志查看器、代码地图、Jupyter、外部应用卡片、应用级长文案 |
| `zh_ui_learn.py` | 学习中心的分类与主题标题（正文保持英文） |

### 带变量的句子

`render()` 支持 `{name}` 形式的模板，匹配时会捕获实际内容：

```python
UI_TEXT = {"Found {n} environments": "找到 {n} 个环境"}
render("Found 7 environments")     # -> "找到 7 个环境"
```

## 四、测试

```bash
python -m pytest tests/test_i18n.py tests/test_i18n_qt.py -q
```

- `tests/test_i18n.py`：词表完整性（`en` 的每个 key 在 `zh` 都有）、
  `render()` 对未知文本原样返回、`canonical()` 反向映射、
  「切到英文再切回来仍是同一句中文」（不重复翻译）、模板捕获、语言监听只触发一次。
- `tests/test_i18n_qt.py`：真实控件层的验证（标签、按钮、页签、表头、占位符被翻译，
  表格数据不被翻译，来回切换不叠加）。**没有装 PySide6 时整文件自动跳过**，
  所以 CI 里装不装 Qt 都能跑。

## 五、CI 自动编译

`.github/workflows/build.yml`：

| 触发 | 行为 |
|---|---|
| push 到 `main` | 跑测试 + 编译 Windows / macOS / Linux(AppImage)，产物作为 Artifact 上传 |
| Pull Request 到 `main` | 同上（不发布） |
| push tag `v*` | 额外创建 Release 并发布到 PyPI |
| 手动 `workflow_dispatch` | 同上，可手点 |

构建产物：Actions 运行页底部的 **Artifacts**（`VenvStudio-Windows`、
`VenvStudio-macOS`、`VenvStudio-Linux-AppImage`、`VenvStudio-Linux`）。

> 只想本地验证中文界面：`QT_QPA_PLATFORM=offscreen python main.py`（Linux 无显示环境），
> Windows 直接运行即可。

## 六、已知边界

- **学习中心的正文仍是英文**。那里是几千行技术教程，属于「翻译内容」而不是
  「翻译界面」；标题、分类、按钮已经汉化，正文留待单独推进。
- 少数由字符串拼接生成的提示（例如 `"Found " + n + " package(s)"`）没有对应词条，
  会保持英文。要给它们加中文，需要把源码改成整句（推荐 `tr()` + 模板）。
- 其它语言（tr/de/fr/es/pt/ru/ja/ko/ar）只有 `tr()` 键值层的翻译，
  文本层词表目前只有中文。新增语言时按同样的 `zh_ui_*` 结构加一套即可。
